# SMS 보조 라벨 Taxonomy v2

## 기본 원칙

- `label`은 모델 학습 정답이며 `normal` 또는 `phishing`만 허용한다.
- `type`은 오류 분석을 위한 보조 라벨이다.
- 하나의 메시지에는 대표적인 공격 목적을 기준으로 하나의 type을 지정한다.
- 키워드만으로 자동 분류한 결과를 정답으로 사용하지 않는다.

## 피싱 type 판정 기준

| Type | 판정 기준 |
|---|---|
| 정부공공기관사칭 | 정부·공공기관을 사칭하여 금전 또는 행동을 요구 |
| 수사기관사칭 | 경찰·검찰·법원 등을 사칭하여 수사·체포 등을 빌미로 요구 |
| 금융기관사칭 | 은행·카드·금융사를 사칭 |
| 대출사기 | 대출 승인·저금리 전환·선입금 등을 유도 |
| 택배배송사칭 | 배송·주소 오류·송장 확인 등을 빌미로 링크 접속 유도 |
| 결제환불사칭 | 허위 결제·환불·취소를 빌미로 행동 유도 |
| 지인가족사칭 | 가족·지인·직장 관계자를 사칭 |
| 경조사사칭 | 청첩장·부고·돌잔치 등의 확인을 유도 |
| 이벤트당첨사칭 | 당첨·쿠폰·지원금 수령을 빌미로 개인정보 또는 접속 요구 |
| 채용부업사기 | 채용·고수익 부업·리뷰 알바 등을 빌미로 금전 요구 |
| 투자리딩방사기 | 주식·코인·투자방 가입 및 입금을 유도 |
| 중고거래사기 | 중고거래 결제·안전결제·배송을 빌미로 금전 또는 접속 요구 |
| 계정정지본인인증유도 | 계정 정지·도용·인증 만료 등을 빌미로 인증 유도 |
| 악성링크앱설치유도 | 특정 사칭 주체보다 링크 접속·앱 설치가 핵심인 유형 |
| 복합피싱 | 서로 다른 두 개 이상의 공격 목적이 동등하게 나타남 |
| 기타피싱 | 근거 부족으로 다른 유형을 확정할 수 없음 |

## 복합 및 모호한 사례 처리

1. 사칭 주체보다 최종 행동 오구를 우선한다.
2. 배송 주소 오류와 악성 링크가 함께 있으면 `택배배송사칭`으로 분류한다.
3. 금융기관 사칭과 저금리 대출 유도가 함께 있으면 `대출사기`로 분류한다.
4. 두 목적이 동등하면 `복합피싱`으로 분류한다.
5. 판단 근거가 부족하면 `기타피싱`으로 남기고 검토 사유를 기록한다.

## 최소 표본 기준

- 정식 type 유지 권장 기준: 20건 이상
- 20건 미만이면 유사 상위 type과 병합하거나 `기타피싱`으로 유지
- Test 유형별 성능을 공개할 때 표본 수를 반드시 함께 표시
