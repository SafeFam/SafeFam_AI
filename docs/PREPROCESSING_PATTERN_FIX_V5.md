# 전처리 패턴 수정과 v5 재판정 결과

Issue #92 · 전처리 패턴이 정상 문자와 금액 변형을 잘못 처리하는 문제

## 1. 목적과 결론

`#89`에서 실데이터를 보강해 재학습한 결과 오탐은 줄었으나 피싱 포착률이 0.892에서 0.783으로 떨어졌다. 원인은 데이터가 아니라 전처리 패턴 세 개로 확인됐다.

세 패턴을 고치고 재학습했다. **자동 경고 오탐이 실제 문자 평가셋에서 0건이 됐고 포착률도 일부 회복됐다.** 다만 포착률은 여전히 기준에 못 미쳐 판정은 `FAIL`이다.

회복의 공은 세 패턴에 고르게 있지 않다. `PERSONAL_INFO_PATTERN`은 고친 뒤에도 pool 836건 중 피싱 1건에서만 켜져 사실상 기여하지 않는다(3장).

## 2. 고친 것

### 2.1 `PERSONAL_INFO_PATTERN` — 요구 문형으로 좁힘

`인증번호` 같은 단어의 존재만 보던 것을, 자격증명 명칭과 **넘김 요구**가 함께 나올 때만 켜지도록 바꿨다.

핵심은 `입력`을 요구 표현에서 뺀 것이다. 정상 인증 문자가 바로 그 표현을 쓴다.

```
인증번호를 입력해주세요   →  0   본인이 직접 입력
인증번호를 알려주세요     →  1   제3자에게 전달
```

### 2.2 `ACCOUNT_PATTERN` — 전화번호 배제

패턴 자체는 두고, 매치된 숫자가 전화번호로도 완전히 읽히면 계좌로 세지 않는 `contains_account_number`를 추가했다. 계좌 형식은 은행마다 달라 앞자리로 거를 수 없다.

패턴을 그대로 둔 이유는 마스킹 때문이다. `normalize_text`가 이 패턴을 쓰므로 바꾸면 fingerprint가 흔들린다.

### 2.3 `AMOUNT_PATTERN` — 한글 단위 포함

`113만 원`, `3만원`, `1억 2천만원` 같은 표기를 잡도록 확장했다. 공백은 한 칸까지만 허용해 줄바꿈 너머의 `원`을 삼키지 않게 했다.

## 3. 특징 판별력 회복

피싱과 정상의 보유율 차이다. 클수록 판별에 유용하며, 최종 pool 836건 기준이다.

| 특징 | `#89` 이후 (968건) | **`#92` 이후 (836건)** |
|---|---:|---:|
| `has_personal_info_request` | -0.005 | **+0.0032** |
| `has_account` | -0.058 | **+0.0760** |

두 특징 모두 음수에서 양수로 돌아섰다. 정상 인증 문자에서 `has_personal_info_request`는 한 건도 켜지지 않는다.

다만 **`has_personal_info_request`는 사실상 죽은 특징이다.** 836건 중 피싱 1건에서만 켜진다. 4장의 중복 제거로 이 표현을 담은 피싱이 대부분 같은 문장의 변형이었음이 드러났고, 대표 한 건만 남았다. 따라서 5장의 포착률 회복은 이 패턴이 아니라 `ACCOUNT_PATTERN` 수정과 중복 제거가 만든 결과로 봐야 한다.

`has_phone`은 -0.067로 음수 그대로다. 소상공인 광고에 연락처가 실제로 많아서이며 패턴 오류가 아니다.

## 4. 데이터 변화

금액 마스킹이 넓어지면서 중복 제거가 강해졌다.

| | 이전 | 이후 |
|---|---:|---:|
| 고유 fingerprint | 1,247 | **1,114** |
| 학습 pool | 968 | **836** |
| ㄴ 정상 | 581 | 527 |
| ㄴ 피싱 | 387 | **309** |

피싱이 78건 줄었다. `#84`가 지목한 숫자 변형 중복이 피싱 쪽에 몰려 있었기 때문이다.

**평가셋(`real_holdout` 157건)은 표본 단위로 동일하다.** 이전 패턴으로 되돌려 같은 절차를 다시 돌린 뒤 텍스트 집합을 대조해 확인했다. 따라서 v3·v4와 판정을 비교할 수 있다.

판정셋 지문은 원문을 해싱한다. 마스킹 결과를 쓰면 전처리를 고칠 때마다 값이 달라져, 평가셋이 고정됐다는 근거가 되지 못하기 때문이다.

split은 v5로 재생성했다.

## 5. 판정 결과

판정 split `real_holdout` (세 버전 모두 동일한 157건)

| 항목 | v3 | v4 | **v5** | 기준 | 판정 |
|---|---:|---:|---:|---:|---|
| 정상 표본 수 | 74 | 74 | 74 | ≥ 300 | 판정불가 |
| 피싱 표본 수 | 83 | 83 | 83 | ≥ 60 | 통과 |
| 피싱 포착률 | 0.8916 | 0.7831 | **0.8434** | ≥ 0.95 | **미달** |
| 자동 경고 오탐률 | 0.0541 | 0.0135 | **0.0000** | ≤ 0.01 | 통과 |
| '의심' 정상 비율 | 0.0676 | 0.0676 | 0.0676 | ≤ 0.10 | 통과 |
| P95 지연시간 | 9.70 ms | 13.97 ms | 15.66 ms | ≤ 50 ms | 통과 |

### 종합: `FAIL` — 승격하지 않는다

포착률 0.8434는 피싱 83건에서 측정한 값으로, 기준 0.95에 대한 **확인된 미달**이다. 정상 표본 수는 여전히 부족해 오탐률 항목은 `INSUFFICIENT_EVIDENCE`로 남지만, 확인된 미달이 하나라도 있으면 종합 판정은 `FAIL`이다(4장 우선순위).

그 전제에서, **측정된 자동 경고 오탐은 0건이다.** 실제 문자 74건에서 오경보가 한 건도 없다. 표본이 300건에 이르러야 이 값이 상한 1% 준수의 근거가 된다.

포착률은 `#89`의 하락분을 절반쯤 되돌렸다(0.783 → 0.843). 다만 v3 수준(0.892)에는 못 미치고 기준 0.95와는 여전히 거리가 있다.

각 artifact는 자신이 학습된 전처리로 평가했다. 실제 운영 조건과 같은 비교다.

## 6. 남은 제약

1. **포착률 0.843 → 0.95.** 남은 격차의 성격은 아직 특정되지 않았다. 데이터인지 특징인지 모델인지 다음 분석이 필요하다.
2. **평가셋 정상 74건.** `normal_sample_size ≥ 300` 미달로 판정은 계속 `INSUFFICIENT_EVIDENCE`를 벗어나지 못한다. 오탐 0건이 상한 1% 준수의 증거가 되려면 표본이 그만큼 있어야 한다. 별도 이슈에서 다룬다.
3. **상한 1%로는 여전히 운영점이 없다.** artifact는 `--max-false-positive-rate 0.10`으로 만든 실험용이며 `artifacts/stacking/v5-experiment`에 있다. 정규 경로 `v5`는 비어 있다.
