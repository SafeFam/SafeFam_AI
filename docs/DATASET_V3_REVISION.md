# SMS 데이터셋 v3 정비 보고서

Issue #83 · 정상 SMS 데이터 정비 및 실제 데이터 기반 holdout 재구성

## 1. 목적과 결론

#78에서 Stacking v2는 독립 Test 136건 중 정상 60건 가운데 59건을 피싱으로 분류했다(오탐률 98.33%). 이 보고서는 그 원인을 데이터 관점에서 규명하고 데이터셋을 정비한 결과를 기록한다. 모델 채택 판정은 이 이슈의 범위가 아니다.

확인된 원인은 두 가지다.

1. **정상 문자 유형 편중** — 학습 pool의 정상 415건 중 392건(94%)이 `기타정상`과 `일상대화` 두 덩어리였고, 피싱과 짝이 되는 정상 알림은 통틀어 23건뿐이었다.
2. **평가셋이 전부 합성 데이터** — holdout 210건이 `synthetic_new_holdout`과 `synthetic_fp_stress`로만 구성돼 실제 성능을 판정할 수 없었다.

정비 후 동일 파이프라인으로 학습한 결과, 실제 문자 평가셋에서 ROC-AUC가 0.9357로 측정됐다. 정비 전 v2 artifact를 실제 split에 적용했을 때의 0.72~0.83과 대비된다.

**결론: 데이터셋 v3을 후속 재학습의 기준 데이터로 확정한다.**

### 2.2 평가셋 구성

정비 전 holdout 210건의 source는 `synthetic_new_holdout` 105건과 `synthetic_fp_stress` 105건이었다. 실제 문자는 한 건도 없었다.

이 holdout에서 v1과 v2 모두 ROC-AUC 1.0으로 측정됐으나, 동일 artifact를 실제 문자로 구성된 split에 적용하면 validation 0.7210 / test 0.8296이었다. 합성 데이터가 템플릿에서 생성돼 자명하게 분리되는 탓이며, 이 평가셋으로는 실제 성능을 판정할 수 없다.

## 3. 정비 내용

### 3.1 정상 문자 유형 재분류

`analyze_sms_taxonomy.py`와 `apply_sms_type_annotations.py`를 `--label`, `--current-type`으로 파라미터화해 정상 문자에도 적용할 수 있게 했다. `proposed_type` 허용 목록도 label에 따라 갈리도록 `allowed_types_for_label()`을 추가했다.

`기타정상` 219건과 `일상대화` 173건을 템플릿 그룹 305개 단위로 검수해 재분류했다. 이진 label과 원문은 변경하지 않았다.

| 유형 | 재분류 전 | 재분류 후 |
|---|---:|---:|
| 정상금융알림 | 1 | 33 |
| 정상택배배송안내 | 2 | 33 |
| 정상카드결제알림 | 1 | 30 |
| 정상광고프로모션 | 1 | 42 |
| 정상공공기관알림 | 1 | 10 |
| 정상인증알림 | 1 | 8 |
| 정상포인트소멸알림 | 16 | 17 |
| 기타정상 | 219 | 69 |
| 일상대화 | 173 | 173 |

판단이 갈릴 수 있는 25건은 `review_note`에 근거를 남겼다. 주요 결정은 다음과 같다.

- CJ 뒤에 기관명을 붙인 배송 안내 13건 → `정상택배배송안내`. source가 `original`이며 발신처명이 변형된 hard negative로 판단
- 은행 발신 소비쿠폰 사용 알림 9건 → `정상카드결제알림`. 광고가 아닌 사용 내역
- 카드 실물 배송 안내 2건 → `정상택배배송안내`
- 토스 비밀번호 변경·로그인 알림 2건 → `정상인증알림`

### 3.2 취약 유형 보강

재분류 후에도 부족한 유형에 hard negative 76건을 추가했다. source는 `synthetic_normal_v3`으로 태깅했다.

| 유형 | 추가 |
|---|---:|
| 정상인증알림 | 22 |
| 정상공공기관알림 | 20 |
| 정상금융알림 | 17 |
| 정상택배배송안내 | 17 |

피싱과 혼동되는 요소(기관명, 금액, 시각, 인증번호, 공식 URL 4건)를 포함하되 문장 구조를 다르게 두어 중복 제거에서 살아남도록 구성했다.

### 3.3 실제 데이터 기반 holdout

`build_real_holdout.py`를 추가해 학습 pool의 실제 문자 중 156개 템플릿 그룹(고유 157건)을 평가 전용으로 분리했다.

- 템플릿 그룹 전체를 통째로 이동해 학습셋과의 누수를 차단했다.
- 합성 행이 한 건이라도 포함된 그룹은 후보에서 제외해 평가셋 오염을 막았다.
- label과 세부 유형 비율을 유지하되, 표본 10건 미만 유형은 학습에 남겼다.

기존 합성 셋은 주 평가셋에서 보조 FP 스트레스 셋으로 역할을 낮췄다. `select_real_holdout()`과 `select_synthetic_stress()`로 구분해 사용한다.

평가셋에도 중복 제거를 적용했다. 적용 전 홀드아웃은 929행이었고 그중 한 템플릿은 36회 반복됐다. 중복을 남겨두면 지표가 반복 횟수가 많은 문자 몇 건에 좌우된다.

| 평가셋 | 건수 | 피싱 | 정상 |
|---|---:|---:|---:|
| real_holdout | 157 | 83 | 74 |
| synthetic stress | 123 | 68 | 55 |

### 3.4 Split 구성 개선

정비 전 split은 세부 유형이 한쪽에 몰렸다. 대표적으로 `지인가족사칭` 47건이 train 29 / validation 18 / test 0으로 배정돼, validation에서 고른 threshold가 test로 전이되지 않았다.

`dataset_splitting`에 세 가지를 추가했다.

1. **유형 분포 오차** — 후보 점수에 label 분포와 함께 유형 분포의 L1 거리를 반영
2. **유형 누락 비용** — 양쪽 중 한 곳에라도 없는 유형의 표본 비중 합을 점수에 추가. 비중으로 가중해 큰 유형의 누락이 더 비싸다
3. **유형 비례 후보 생성** — 유형마다 group을 섞어 비율만큼 떼되 group이 2개 이상이면 양쪽에 최소 하나씩 남기는 후보 200개를 무작위 후보와 함께 평가

점수 순서는 유형 누락 → 크기 등급 → 분포 오차 → 크기 오차다.

| 유형 (표본 5건 이상) | 정비 전 | 정비 후 |
|---|---|---|
| 지인가족사칭 (39) | validation 0건 | 해소 |
| 투자리딩방사기 (21) | validation 0건 | 해소 |
| 대출사기 (5) | validation 0건 | 해소 |
| 채용부업사기 (15) | test 0건 | validation 0건 (구조적 한계) |

`채용부업사기`는 15건이지만 템플릿 그룹이 2개다. 그룹 무결성을 지키면서 세 split에 배분하려면 그룹이 최소 3개 필요하므로 현재 데이터로는 배치할 수 없다. 그룹이 3개 이상인 유형은 모두 세 split에 나타난다.

## 5. 남은 과제

1. **정상 문자 76건이 합성이다.** `synthetic_normal_v3`은 학습 pool 전용이며 평가셋에 포함하면 안 된다. 실제 수집분으로 대체하는 것이 바람직하다.
2. **재분류 검수가 사람 검수가 아니다.** 305개 그룹의 `proposed_type`은 자동 분류 초안을 승인한 결과다. 특히 유형 경계가 애매한 25건은 팀 기준 확정이 필요하다.
3. **`채용부업사기` 템플릿 다양성이 부족하다.** 15건이 2개 템플릿의 변형이라 split 배치가 불가능하다. 서로 다른 문구의 표본 확보가 필요하다.
4. **정상 오탐률이 아직 서비스 가능한 수준이 아니다.** real_holdout 기준 14.86%다. 단독 운영 채택 기준과 threshold 정책은 후속 이슈에서 정한다.
5. **`정상광고프로모션`과 `정상공공기관알림`에 오탐이 남는다.** Test split에서 각각 5/8, 3/4다. 다음 재학습에서 유형별 FP를 다시 확인해야 한다.
