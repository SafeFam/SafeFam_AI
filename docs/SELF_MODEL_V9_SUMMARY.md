## 무엇을 고쳤나

**1. 프로덕션 아티팩트가 고장나 있었습니다** (`#112`)

배포 경로의 모델이 2026-08-11에 구조 특징 15개로 학습됐는데, 이후 피처가 추가되면서 코드는 20개를 만들고 있었습니다.

```
ValueError: X has 20 features, but LogisticRegression is expecting 15
```

앱이 예외를 잡아 `is_available=False`로 처리한 탓에 서비스는 죽지 않았고, **그래서 아무도 눈치채지 못한 채 자체 모델이 무력화돼 있었습니다.**

재발 방지 테스트를 추가했습니다. 아티팩트가 코드·데이터와 어긋나면 CI가 잡습니다. 실제로 `#111` 머지 과정에서 한 번 걸러냈습니다.

**2. 학습 데이터에 기관명 교체 오염이 있었습니다** (`#111`)

1,144자 같은 본문에서 은행 이름 2~5글자만 바꾼 복제본 9벌이 임계값 근처에 뭉쳐, 피싱 탐지 여유분을 독식하고 있었습니다. 22건을 제거했습니다(그룹당 대표 1건 유지, 정보 손실 없음).

**3. 기관 등록 정보를 전수 검증했습니다** (`#109`)

25개 기관의 공식 도메인·대표번호를 교차 확인했고, 우체국의 예금·보험 채널 누락을 보완했습니다.

## 채택 게이트: 여전히 FAIL

LLM 없이 자체 모델만으로 운영하려면 6개 기준을 통과해야 하는데, `'의심' 정상 비율`이 미달입니다(0.3651 vs 기준 0.133).

**원인은 데이터입니다.** 오탐이 남은 유형은 실수집 학습 데이터가 7~18건뿐입니다.

| 정상 유형 | 실데이터 | 합성·증강 | v9 오탐률 |
|---|---:|---:|---:|
| 일상대화 | 136 | 3 | 6.1% |
| 정상공공기관알림 | 9 | 32 | 38.7% |
| 정상카드결제알림 | 7 | 48 | 29.6% |

실데이터 비율과 오탐률이 그대로 역상관입니다. 자세한 내용과 기각한 가설들은 [`STANDALONE_ADOPTION_CRITERIA.md`](./STANDALONE_ADOPTION_CRITERIA.md) 5장에 있습니다.

## 검토가 필요한 사항

**① 인코더 도입 여부 — 지금은 보류를 권합니다**

한국어 인코더를 파인튜닝하면 LLM 호출이 31.3% → 18.1%로 더 줄지만, 배포 환경(`t3.small` 2 vCPU)에서 실행할 수 없습니다.

| 필요한 것 | |
|---|---|
| 더 빠른 CPU | 현재 인코더 P95가 예산 초과 |
| `torch` 추가 | 이미지 400MB → 1.1GB |
| 메모리 | +605MB (2GiB에서 여유 부족) |

**손익분기 약 월 35만 건**입니다(인스턴스 차액 ~$45/월 ÷ 절감 ~$0.13/1,000건). 그 미만이면 순손실입니다.

또한 하이브리드 운영 중에는 '의심' 구간을 LLM이 판단하므로 **사용자가 받는 정확도는 양쪽이 같습니다.** 인코더의 이득은 비용·지연시간이지 품질이 아닙니다.

**② 실수집 정상 문자 확보 — 게이트 통과의 유일한 경로**

카드결제·공공기관·광고 유형의 실제 정상 문자가 유형당 50건 이상 필요합니다. **합성 데이터로는 대체할 수 없습니다** — 이미 211건이 있으나 실데이터보다 뚜렷하게 쉬워, 오탐이 남은 유형이 정확히 합성 비율이 높은 유형입니다.
